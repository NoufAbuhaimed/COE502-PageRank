# Q1 — Speedup and efficiency analysis

Everything from a fresh server to the speedup and efficiency tables in the report: get the code onto
the server, check that it finds the graphs, check correctness, run the timing benchmark (safe to resume after a Spot
stop), and paste the tables into the Google Doc. Q2–Q5 reuse the results produced here, so do this
one first.

PDF sections covered: *OpenMP experiments* (thread scaling, problem size, scheduling) and
*Performance analysis* (S_p = T1 / T_p, E_p = S_p / p, the point where threads stop helping).

---

## 1. Get the code onto the server

On your laptop, push first:

```bash
cd ~/"COE502_Project/page-rank"
git push
```

On the server (first time):

```bash
git clone git@github.com:NoufAbuhaimed/COE502-PageRank.git ~/COE502-PageRank
cd ~/COE502-PageRank
```

On the server (every later time):

```bash
cd ~/COE502-PageRank && git pull
```

All commands below run from `~/COE502-PageRank` on the server.

## 2. Install prerequisites and build

```bash
./scripts/setup.sh        # g++ with OpenMP, make, uv; ends with "OK: ..."
make                      # builds ./serial ./parallel ./parallel_opt
```

## 3. Check the graphs are where the scripts look

Nothing to copy. Every script reads the provided graphs from one place (`scripts/data_dir.sh`):

| Machine | Graph folder |
| --- | --- |
| Course server | `/workspace/coe502/datasets` (used whenever it exists) |
| Our own machines | `../datasets`, next to the repo: `~/COE502_Project/datasets` |

`DATA=<folder>` in front of any command overrides both.

On the server, check the six graphs are there (about 160 MB in total):

```bash
ls -lh /workspace/coe502/datasets/
```

On your own machine, unpack them next to the repo once:

```bash
cd ~/COE502_Project && unzip -o dataset.zip -d datasets && ls -lh datasets/
```

The 5-node test graph `tiny_dangling.txt` is ours and stays in the repo's `datasets/` folder.

## 4. Check correctness (needed for the report anyway)

```bash
make check
```

The last line must be `All checks passed.` This writes `results/correctness.csv` (used in Q5).

## 5. Pick the iteration count

The PDF asks for a serial run of roughly 5–15 s on the large graph. The default is 1000
iterations. Check it on this machine:

```bash
./serial /workspace/coe502/datasets/pr_s500k_5m.txt 1000 0
```

The last number on the line is the time in seconds. If it is between 5 and 15, keep the default.
If not, scale it, for example 2.5 s → use `ITERS=3000`. Use the same value for every later
command; the benchmark refuses to mix iteration counts in one CSV.

## 6. Run the benchmark inside tmux

`tmux` keeps the benchmark running if your SSH connection drops.

```bash
tmux new -s bench
make bench 2>&1 | tee -a results/bench.log
```

(With a different iteration count: `ITERS=3000 make bench 2>&1 | tee -a results/bench.log`.)

- **What it runs:** 560 runs. Main experiment: serial, plus static, dynamic,64 and edge-balanced
  at 1, 2, 4, 8 and 16 threads, on all six graphs. Chunk sweep: dynamic with chunks 16–4096 at
  8 and 16 threads, on the medium and large skewed graphs. Each configuration runs 5 times.
- **How long:** roughly 20–30 minutes with ITERS=1000.
- **Detach / reattach:** `Ctrl-b` then `d` to leave it running; `tmux attach -t bench` to come back.

**If the Spot VM is stopped:** start the VM, then run the same thing again. Finished runs are
skipped; a half-written last line is removed and redone.

```bash
cd ~/COE502-PageRank && tmux new -s bench
make bench 2>&1 | tee -a results/bench.log
```

**Check it is complete:** 560 runs (5 per configuration). Starting `make bench` again would also
print `plan: 560 runs, 560 already in ...` and exit.

```bash
tail -n +2 results/raw_timings.csv | wc -l
```

## 7. Compute medians and draw the plots

```bash
make plots
```

This writes `results/summary.csv` and `plots/*.png` and prints a table per graph.

## 8. Paste the tables into the Google Doc

Save the Markdown tables to a file (keeps a copy in the repo too):

```bash
mkdir -p report
uv run scripts/report_tables.py speedup knee | tee report/q1_tables.md
```

Copy the output into the Google Doc under **Speedup & Efficiency Analysis**:

1. In Google Docs: **Tools → Preferences → Enable Markdown** (once).
2. Copy the terminal output, then in the doc: **right-click → Paste from Markdown**
   (or **Edit → Paste from Markdown**). The tables become real tables.

Insert `plots/speedup_overview.png` and the `plots/scaling_*.png` files there too. To download
them, see [Q4 §2](Q4.md#2-download-the-plots-to-your-laptop).

## 9. Save the results back to Git

```bash
git add results/ plots/ report/
git commit -m "Benchmark results: raw timings, summary and plots"
git push
```

If the server can't push (no GitHub key there), copy the folders to your laptop instead (on the
**laptop**):

```bash
scp -r <user>@<server>:~/COE502-PageRank/{results,plots,report} .
```

## 10. What to write in this section

Answer these from your own tables and plots. Each one should quote at least one number.

| Question | Where the answer is |
| --- | --- |
| How do speedup and efficiency change from 1 to 16 threads, for each version? | `speedup` table, `scaling_*.png` |
| At what thread count does adding threads give little or no benefit, and is it the same for every graph? | `knee` table ("Diminishing from P") |
| How do the small, medium and large graphs differ, and why does the small graph scale worst? | `speedup_overview.png` columns |
| How do uniform and skewed graphs differ at the same size? | `speedup_overview.png` rows |
| Which schedule is fastest on each graph, and by how much? | `speedup` table at P = 8 and 16 |
| Is the speedup at P = 1 above or below 1.0, and why would a parallel build at one thread differ from the serial program? | `speedup` table, P = 1 rows |
